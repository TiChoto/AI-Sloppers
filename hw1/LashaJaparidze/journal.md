# Pattern Journal · LashaJaparidze · Weeks 1 to 4

*Copied from `docs/journal/LashaJaparidze.md`. One entry per teaching week: the pattern, where I used it, what I delegated, how I verified it, one thing I would do differently.*

**W1 · Context as Budget** · Week 1 · **Where:** the context list in my HW1 spec. `decide()` gets two things: the draft and the seller's text. It does not get the image, the listing store, or FastAPI. The agent's context is five named files, and Luka's listing model is read only, for the five condition values. **Delegated:** the napkin math. It came back as an estimate of about $0.0009 per upstream draft, using the course price table. **Verified:** the arithmetic by hand: 400 × $0.75/M + 150 × $3.75/M ≈ $0.00086. I labelled it "estimated, not measured" because there is no `logs/usage.jsonl` yet. **Do differently:** replace the estimate with logged tokens as soon as the team's listing assistant makes a real call.

**W2 · Spec Before Code** · Week 2 · **Where:** the first version of this folder. Its spec said "reject non-positive or invalid prices" for `POST /listings/`, and its golden set expected `HTTP 200`. Luka's real API returns `201`, and that scope was already Luka's HW1. The log also claimed code that was never in `src/`. **Delegated:** the rewrite to six criteria a script can decide, including an error case (exit 2, nothing on stdout) and a latency bound (1,000 calls in under 1 s). Tests were written from those criteria before `checks.py`. **Verified:** each criterion has a named test or golden question (`golden.md`). **Do differently:** read my teammates' `hw1/` folders before picking a feature, not after.

**W3 · Uncertainty-Aware UX** · Week 3 · **Where:** DraftCheck itself, which follows the Lab 3 pattern. The model's draft carries `value / evidence / confidence`. A pure `decide()` routes it to accepted, confirm, review or rejected. Hard fields reach the seller's form **empty**, never prefilled. Price is stricter than the reference: evidence the seller did not write (for example from the photo) is a hard flag. **Delegated:** the tests and the code. **Verified:** deliberate breaks. Swapping the evidence and confidence checks first went unnoticed (`29 passed`), because my test used confidence 0.99. With confidence 0.2 the break is caught. **Do differently:** write the test for "evidence before confidence" with a *low* confidence from the start. A test that cannot fail does not count as evidence.

**W4 · Grounded Generation** · Week 4 · **Where:** the same rule as a RAG citation check, applied to a draft. A citation must point at a source that was retrieved, and a draft's evidence must point at something the seller actually wrote. Golden question 2 shows why: the model wrote the price `45.00` *and* the evidence `"45 GEL"` at confidence 0.9, with no price anywhere in the seller's text. A null-evidence check alone would have accepted it. In the team's Design Review (20 Oct), §4 records our golden set as "not run". That is honest, but it is a gap. **Delegated:** writing the three golden inputs. **Verified:** I ran all three through the CLI and pasted the real outputs into `golden.md`. **Do differently:** make the team's first golden set include a "model invents the evidence" case, not only "model returns null".
